WTVP server


Where the Bridge sends the box's WebTV service connections (ports 1600 to 1699): a name or an address.
Blank: wherever the box asks. The Bridge keeps it, and the TV's Settings shows the same one.


 


DNS server


Where the Bridge looks up names (the WTVP server's, and the box's).
Blank: the router's, or 8.8.8.8 when it gives none.


 







The Bridge reads and writes the box's disk through its loader, which runs only before the OS starts.
So these work only while the TV shows the WebTV Bridge screen (Start now, Settings), the one that comes up
when the box is switched on or restarted. Starting one stops that screen's countdown, so the OS waits until you start it.

Save this OS
Reads the OS from the box's disk, as it is there, and downloads it.



Install another OS
Writes an OS image (an _approm.o) to the slot the box isn't booting; it boots from then on.
Keep the box on until it's done.

  






Grabs the picture the box is putting on the TV. The OS's screens are put together by the SOLO's compositor
from many small pieces (cels), so the page reads those and the memory they draw from, and composites them the way the
emulator does; the WebTV Bridge screen is a plain framebuffer. While the OS runs, the OS reads its memory for the Bridge,
a little at a time over the parallel port (something moving on the screen meanwhile may tear); on the WebTV Bridge
screen the Bridge's loader reads it.

The box's disk: its partitions, the areas of the boot partition outside them, and the files in its FAT filesystems.
The Bridge reaches the disk through its loader, so only while the TV shows the WebTV Bridge screen; the OS isn't running
then, so nothing else is using the disk. Writes go straight to the box's disk: download a partition first to keep a copy.
